### 现象层（What）

**09-30 6 段产出** = `self_reflective_wrapper_v0_1.py`（253 行），但**只支持 `RECOVERY_GUIDANCE` 一种 type**（论文 §3.1.3 两种 type 之一）。

### 机制层（Why）

**论文 §3.1.3 双 type 设计的必要性**：

| Type | 时机 | 输入 | 输出 | 用途 |
|---|---|---|---|---|
| **INTENT_DISAMBIGUATION** | 调用前 | 用户原始 query | 2-4 个候选解释 + confidence | 解决"用户说'最近'，agent 不知道是 1d/1w/1m"的歧义 |
| **RECOVERY_GUIDANCE** | 失败后 | 失败响应 | 5-10 条 actionable suggestions | 解决"akshare 挂了，agent 不知道下一步怎么办" |

**为什么双 type 必需**：论文 §6.2.4 **action-verb bottleneck** 揭露 — 单 type 只能让 agent 在"已发生的错误"上做 recovery，无法阻止"原本就不该犯的错误"（歧义输入导致 cascade 失败）。

### 实现层（How）

**新脚本**：`/workspace/scripts/self_reflective_wrapper_v0_2.py`（**582 行**）— v0.1 的 2.3 倍规模

**核心新增组件**：

#### A. `IntentDisambiguator` 类（前置于 recovery）
3 类歧义检测（启发式，可接 LLM judge）：
1. `symbol_6_digits_may_be_hk_or_a_or_bj` — "000001" 是 A 股/港股/北交所？
2. `time_window_unspecified` — "最近" = 1d/1w/1m/1q？
3. `magnitude_unspecified` — "大幅" = +5%/+10%/+20%/+50%？

#### B. 18 个 ActionType 枚举
- **Recovery 类**（10 个）：SWITCH_DATA_SOURCE / NOTIFY_USER / USE_CACHED_DATA / RETRY_WITH_DELAY / FIX_PARAMETERS / ABORT_OPERATION + WAIT_AND_RETRY / USE_FALLBACK_DEFAULT / REQUEST_CLARIFICATION / RUN_DIAGNOSTIC
- **Intent 类**（4 个）：CLARIFY_INTENT / INFER_FROM_CONTEXT / USE_DEFAULT_INTERPRETATION / PROVIDE_MULTIPLE_RESPONSES
- **Diagnostic 类**（4 个）：AUDIT_LEAKAGE / TAG_DATA_SOURCE / REPLAY_WITH_HISTORY / DEFER_TO_HUMAN

#### C. Envelope Dispatcher
```python
def dispatch_response(resp):
    if resp.feedback.type == RECOVERY_GUIDANCE:
        top = max(suggestions, key=confidence)
        return {"dispatched_action": {...}}
    elif resp.feedback.type == INTENT_DISAMBIGUATION:
        top = max(intent_alternatives, key=confidence)
        return {"dispatched_alternative": {...}}
```
