## 2. 三层挖深

### 2.1 现象层 — "每个 agent 都对，团队还是错"

### 2.2 机制层 — Theorem 2.1 + 5 元组 X = (H, C, G, F; D)

**Observation-Aliasing Impossibility Theorem（论文 Theorem 2.1）**：

> A policy can guarantee a valid action from its context **if and only if** every world consistent with that observation allows a common action. With k indistinguishable worlds whose admissible-action sets are pairwise disjoint, best randomized worst-case success = **exactly 1/k**（Theorem 2.3）. **Stronger model cannot see beyond its context.**

**Study I 实证**：LLM 看得到决定事件 → 40/40；看不到 → 12-17/40（与 1/3 随机一致）；加 1 句话恢复 missing fact → 40/40。

**→ wowzai 07:00 自评 8 agent 的根**：8 agent 共享长 context，**每个看到的"决定性事实"都不同** → 评分信噪比被 aliasing bound 压到 ≈ 1/k（k=8 dim ≈ 12.5% 信息）→ 加更多 reasoning/voting/role 也无法恢复

**Coherence Runtime 五元组 X = (H, C, G, F; D)**：


| 组件 | 答的问题 | 失效时丢什么 | wowzai 对应 |
|---|---|---|---|
| **H** dependency graph | 东西在哪 meet？scope/authority/impact | 漏 dependency、change 不传播 | `jobs.json` 21 cron 之间的依赖图 |
| **C** action semantics | action 做什么？precondition/effect/composition | 非法顺序、结果依赖路径 | cron job 触发链 + ToolUse 协议 |
| **G** translation groupoid | 什么是相同的？identity + format translation | duplicated objects、translation loop 不闭合 | self_reward.json ↔ 学习笔记.md ↔ trace 3 个 representation 间的对齐机制（缺失） |
| **F** gluing sheaf | 什么拼得起来？overlap + realization check | 局部兼容但全局无 state | **缺失** —— 这就是 07:00 自评缺的总和检查 |
| **D** history state | 还剩什么相关？version/invalidation/obligation | stale derivation、忘掉的 obligation | traces/*.json + session memory —— 03:00 audit 0/7 字段覆盖率 |


**关键设计哲学（论文 §4.3 Corollary 4.2）**：移除一个 map → 对应 property 失效；加一个 map（在 assumption 下）→ 对应 property 必须成立。**5 元组不是任意选的** —— 它们是"**保留信息在分布/转移/修改过程中不被丢失**"的标准结构。

**Study IV 实证（budget enforcement）**：ordinary team → 5/5 overspend / live count visible → 4/5 overspend / **budget enforced at commit → 0/5 overspend** / per-role escrow → 0/5 overspend

**Study V 实证（silent reverts）**：stock agent → 0/15 解决 / call-time policy checks → 1/15 解决 / **coherence harness → 15/15 解决**

### 2.3 实现层 — Ladder of Strict Diagnostics + wowzai 改造

**arxiv 2609.02142 的 diagnostic ladder（4 层 L1→L4）**：


| 层 | 检查 | 资源 | 信噪比 | wowzai 对应 |
|---|---|---|---|---|
| **L1** | Lenient keyword matching（启发式） | <1 分钟 CPU | ❌ 假阳性（600M/1B 分数相同但行为差 1） | wowzai 当前 self_reward.json 评分 = 这一层 |
| **L2** | Fixed-prompt qualitative battery | 几小时人工 | 🟡 主观 | wowzai 07:00 自由打分 |
| **L3** | **Verbatim-reproduction** + **novel-prompt generalization** | 几小时 GPU | ✅ 实证 | **缺失** —— wowzai 没"verbatim 复现训练数据"这一层 |
| **L4** | **Mechanism probes**（first-token entropy + embedding drift） | 几小时 GPU | ✅✅ 根因定位 | **缺失** —— wowzai 没 token-level 探针 |


**L3 实证数字（论文 Table 4）**：VectraYX-600M verbatim-reproduction **6/6 emit valid tool call** / VectraYX-1B **0/6 at every checkpoint**（B4 score 一致 0.660 vs 0.650 但 verbatim 完全分开）

**L4 实证**：600M 在 `<|tool_call|>` 位置 greedy emit；1B 在同一位置概率仅 **10⁻⁴–10⁻⁵**（几乎没 mass）→ **1B 的 web-heavy 训练 phase 把 earlier prior 擦除了**
