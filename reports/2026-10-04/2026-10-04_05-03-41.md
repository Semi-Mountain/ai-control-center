## 📚 主题1: FloWright (arXiv 2610.01026)

**原文**: https://arxiv.org/abs/2610.01026 | **项目页**: https://xhguo7.github.io/FloWright/

### 现象层
- 多 agent workflow 现有方法**只训练 generator**,执行 agent 永远固定 → workflow 整体提升被锁死
- 扩展到训多 agent 两大难题:(1) 耦合性 (2) **信用分配难**——只有 1 个 sparse score,不知哪个 agent 该背锅

### 机制层
**核心创新 1 — Workflow as Harness**: 不引入额外训练模型,把 workflow 自己当 harness → 训练信号完全 outcome-grounded

**核心创新 2 — Hierarchical Structure-Aware Reward** (5 项 ladder):
```
reward = w_f·f (parse gate) + w_v·v^ρ (validity) + w_e·e (execution) + w_a·a (answer) + Σ_j c_j^ρ (credit per node)
```
- **c_j^ρ 关键**: 每个 role 只为自己 author 的节点背锅 → **自然解决信用分配**
- **拒绝 LLM judge**: "A semantically correct output can also lead to the wrong final answer" → 用 outcome-grounded gain

**核心创新 3 — Mutual Curriculum**: 
- 训三种拓扑: (a) 单 role 自进化 (b) agent+skill 协同 (c) upstream+downstream 协同 (d) 任意 ≥2 role
- 关键机制: 任何 role π_ρ 的训练分布受其他 role π_ρ' 影响 → 不需要手工 curriculum

### 关键数字
| 指标 | 值 |
|---|---|
| 总提升 | **+7.41%** |
| 单 role 自进化 | **+2.83%** |

## 📚 主题2: ASAD (arXiv 2610.00629)

**原文**: https://arxiv.org/abs/2610.00629

### 现象层
- 多 agent debug 框架都是**固定拓扑** — agent 数量、role、interaction 全 hardcode
- 与 bug 异质性矛盾: 简单 bug 浪费 token,复杂 bug 协调不够

### 机制层
**5 维 Static Analysis Features**:
1. Error Severity (failing test 数量)
2. Source-location difficulty (AST depth + NLOC)
3. Program-understanding difficulty (cyclomatic complexity)
4. System-level operations (concurrency)
5. Inter-function dependencies (call graph fan-in/out)

→ **deterministic 信号,evidence-based 决策**——与 SkillSeek 哲学一致

**Adaptive Routing**:
- Low complexity → single-pass (省 32% agent)
- High complexity → multi-agent decomposition

| vs CoT | **+12-20%** |
| vs Static Multi-Agent | **+4-9%** |
| Agent 用量 | **↓32%** |
