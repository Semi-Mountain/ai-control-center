## 🧠 学习内容（三层结构）

### 一、为什么学这个
昨晚 01:00 让 wowzai 具备「每次 cron 比上一次好」的能力。但**没触发 cron 的时间** = wowzai 完全静止（99% 算力浪费）。

### 二、核心范式（Sleep-Time Agents）
| 阶段 | 含义 | 对应 wowzai |
|---|---|---|
| Wake | 用户触发才跑 | cron 触发 = 10min wake |
| Sleep | 用户不触发时**后台运算** | 23h50min sleep |
| Consolidation | episodic → semantic | trace → LOG.md |
| Pre-emption | 预测下次需求 | 周日准备周一面板 |

### 三、5 级实施阶梯（已想明）
- **L0** 当前：空 → **L1** trace 自动评论（今晚落规格 #019）
- **L2** counterfactual replay → **L3** pre-emptive → **L4** 跨段回忆链（#020 候选）
- **L5** 自主觉醒（最高风险）

### 四、2 条今晚新改进（候选）
- **#019** L1 Trace 自动评论：用 LLM 给每条 trace 写批评，作为 sibling file
- **#020** L4 跨段回忆链：每周日 23:50 自动汇总 7 天 trace
- **铁律**：sleep token ≤ 5% wake token

## 💎 3 条核心洞察

1. **从离散到连续**：wowzai 当前是「分时改进」(cron→cron)，sleep-time = 「连续改进」(continuous-time)。这是从「工具」到「员工」的范式跨越。
2. **不动就是浪费**：默认「cron 不跑 = 不学」是错的极端。正确中点 = **10% wake + 5% sleep + 85% idle**。
3. **W39 周末 3 段联合闭环**：00:00 = trace 留底（数据） / 01:00 = 启动外化（机制） / 02:00 = 持续计算（时间）→ **数据 × 机制 × 时间 = 真正可进化的系统**。
