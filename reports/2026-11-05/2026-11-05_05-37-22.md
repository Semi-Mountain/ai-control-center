# 05 段学习报告 · 假绿灯的机械判定

**时间**：2026-11-05 05:00（北京时间，周四）
**主题**：执行域绑定的三轴回执判据 —— 从「返回即成功」到「我确实完成了」

---

## 核心结论

**「任务完成」是环境特定的属性，不是一条 exit status。**

11-04 全天 **22 个 cron job** 中，**11 个是假绿灯**（框架 `last_status=ok` 但零产出）。根因在源码里：

```python
# scheduler.py:895-898 —— success 的唯一来源是「有没有抛异常」
logger.info("Job '%s' completed successfully", job_name)
return True, output, final_response, None
```
```python
# jobs.py:680
job["last_status"] = "ok" if success else "error"
```

API 调用失败在 `run_conversation` 内部被捕获后，**错误文本被当作 agent 的 `final_response` 返回**，于是：
- `## Response` 段 = 429 报错文本（117 字符）　`## Error` 段 = **不存在**
- → `run_job` 返回 `True` → `last_status="ok"` → 报错文本被当正常报告推进飞书

**实测判据结果（v4 脚本 22 job 全量跑）**：
`GREEN=6　PARTIAL(假DEAD)=4　FALSE_GREEN(真假绿灯)=11　DEAD=1`
框架报 ok 的 20 个里，真成功只有 6 个 ⇒ **ok 的 30% 是真的**。

11 个 FALSE_GREEN 的归档 Response 段**长度全部 = 117 字符且文本完全一致** —— 是同一故障的 11 次重演，不是 11 个不同的 bug。

---

## 三层挖深（现象→机制→实现）

| 层 | 发现 |
|---|---|
| **现象** | 08:00/09:25/09:30/11:00/11:30/13:00/13:30/14:00/14:30 等交易 job 全部「亮绿灯但零产出」 |
| **机制** | API 错误被吞成 `final_response` ⇒ `success=True` ⇒ `last_status=ok` ⇒ 报错文本进飞书 |
| **实现** | `scheduler.py:895` 响应体自检 + `:934` finally 块写真实 `end_reason`；`jobs.py:680` 语义不动 |

**为什么数据库和归档都救不了**：`end_reason` 恒为 `cron_complete` —— 因为 `scheduler.py:934` 的 `finally` 块无条件写这个值（21→22/22 session 行实测一致）。归档只有 Prompt + Response，无 transcript。

## 三轴判据（本段最大增量）

```
轴1 run_state    : 进程/调用怎么结束的        (Error段存在? wall timeout?)
轴2 action_state : 产出物是否在【本 job 时间窗内】被写出来 (mtime 夹逼)
轴3 scope_state  : 产出物是否属于【本 job 执行域】(job_id + 时间窗 + 目标路径)
```

只判轴1 漏假绿灯（本次 11 个）；只判轴2 会被跨 job 捡漏（`dist/reports` 的副本是活例子）；**三轴同时成立才算真绿**。

> "successful rehearsal history raises false completion claim rates from 1.9% to 79.7%..."
> "**Changing receipt formatting alone produces no comparable reduction.**"
> "Success is environment-specific..."

即：**光把回执写得更真没用，必须把「这次执行发生在哪」绑上去** —— 这直接否掉了我 receipt emitter v0.1 的一半价值，下一版必须加 `scope` 字段。

## 配额墙 ≠ 限流（关键澄清）

- `agent/rate_limit_tracker.py` 判定的是 **code 2067「Token Plan 用量上限」** —— 硬配额墙，**无 `Retry-After` 可等**
